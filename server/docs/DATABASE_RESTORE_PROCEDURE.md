# 📚 Disaster Recovery & Database Restore Procedure

**Target System**: TG Counselling Platform (`tgicet-simulator`)  
**Database**: Supabase / Managed PostgreSQL  
**Encryption Standard**: AES-256-CBC with PBKDF2 Key Derivation

---

## 1. BACKUP INFRASTRUCTURE OVERVIEW

Automated database snapshots are generated by `server/scripts/backupDatabase.js` and stored in `server/backups/`.

- **Frequency**: Daily automated snapshot execution (or triggered via admin command).
- **Encryption**: AES-256-CBC encrypted using `process.env.BACKUP_ENCRYPTION_KEY`.
- **Retention**: Last 7 daily backup versions retained automatically.
- **Captured Data**: `exams`, `colleges`, `courses`, `categories`, `districts`, `cutoffs`, `users`, `user_checklists`, `eapcet_scrape_cache`.

---

## 2. NON-PRODUCTION RESTORE TEST PROCEDURE (DRY RUN)

To verify the integrity of any backup snapshot without modifying production data:

```bash
cd server
node scripts/restoreDatabase.js
```

**Expected Result**:
The utility decrypts the latest snapshot using `BACKUP_ENCRYPTION_KEY`, parses the payload JSON schema, verifies table row counts, and reports clean verification without altering any production rows.

---

## 3. PRODUCTION RESTORE PROCEDURE (DISASTER RECOVERY)

> [!CAUTION]
> Performing a production restore will replace existing database records with the snapshot payload. Always take a fresh manual snapshot before initiating a restore.

### Step 1: Locate the Backup File
Locate the desired `.json.enc` backup file in `server/backups/` or offsite storage:
```bash
ls -la server/backups/
```

### Step 2: Set Environment Variables
Ensure `DATABASE_URL` and `BACKUP_ENCRYPTION_KEY` are configured in your target environment:
```bash
export DATABASE_URL="postgresql://postgres:[password]@[host]:5432/postgres"
export BACKUP_ENCRYPTION_KEY="your-secure-key"
```

### Step 3: Execute Database Restore
Run the restore script with the `--commit` flag:
```bash
node scripts/restoreDatabase.js --commit server/backups/backup_tgcounselling_[timestamp].json.enc
```

### Step 4: Verify Database Health
Check system health via endpoint:
```bash
curl https://tgcounselling-api.render.com/api/health
```
Verify `{"status":"ok"}` is returned.
